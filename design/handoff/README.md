# Handoff: Portfolio Site — arno1235.github.io (design v1.2.0, desktop + mobile)

## Overview

Redesign of Arno Van Eetvelde's personal site (`arno1235.github.io`): a home page (projects in three tiers, writing, experience, contact) and one detail page per project, in a desktop layout (880 px column) and a mobile layout (single column, tap-sized targets). The visual system is a "quiet spec sheet": two system typefaces (Helvetica Neue for words, Menlo/SF Mono for metadata), five greys per theme, hairline rules, no boxes, no radius, no shadows, no icons, no images except project figures. Light and dark theme. The design's own spec lives inside it as project `00 arno1235` (screenshots desktop-05, mobile-05).

This package supersedes the v1.0.3 handoff. What changed since then: no intro paragraph, no tier notes, no section counters on the right of section lines, no "selected client work" list, the index numbers (`01 projects`, `01.01 engineered`, `YYYY-MM` columns) became **switches that are off**, the theme toggle is a `<button>`, and a mobile layout exists.

## About the design files

`design/Portfolio Site.dc.html` (desktop) and `design/Portfolio Site Mobile.dc.html` (mobile, shown inside an iPhone frame) are **design references built in HTML** — prototypes that show the intended look and behaviour. They are not production code to copy. They run on a small preview runtime (`design/support.js`, plus `design/ios-frame.jsx` for the phone chrome) and keep navigation in memory; the production site must be **static HTML** generated by `_generate_site.py` in the `portfolio` repo, with real URLs and a CSS breakpoint instead of two files.

Open either file in a browser to inspect it: click project names to open detail pages, `light / dark` to switch theme. Every value in this README was taken from those files; when in doubt, the file wins.

## Switches & settings (the "tweaks")

Both prototypes expose the same design-time switches. They exist so options could be compared; the production site **hard-codes** one state. The state to build is the **default** column — it is also how the prototypes are currently set.

| switch | options | default = build this | what it does |
|---|---|---|---|
| `theme` | `system` · `light` · `dark` | `system` | Initial theme of the preview only. The site itself: stored preference → OS preference, plus the `light / dark` toggle (see Interactions). |
| `sectionIndices` | on / off | **off** | On: nav items and section lines get `01 ` … `04 ` prefixes (`01 projects`), tier lines get `01.01 ` / `01.02 ` / `01.03 `. Off: bare words. |
| `projectIndices` | on / off | **off** | On: project rows and writing rows get a leading 64 px mono column with `YYYY-MM`. Off: no date column. |
| `projectsPerTier` | 1 – 15 | **1** | How many projects each tier lists (see Listing algorithm). `00 arno1235` is always listed. When > 1 the tier line appends ` · {count}`. Whether the live site lists 1 or all is an open decision (below). |
| `tier1Name` | `engineered` · `hand-built` · `handmade` · `stable` · `crafted` | **engineered** | Label of the first tier (also shown in the project nav). |
| `tier3Name` | `archived` · `dumpster` · `unfinished` · `graveyard` · `deprecated` | **archived** | Label of the third tier. The middle tier is always `vibed`. |
| `screen` (mobile file only) | `home` · `branding` · `openinsider` · `infurn` · `factory-os` · `sparkplug` · `cutsched` | `home` | Jumps the phone preview to a page. Not a site feature. |

Screenshots `desktop-03` / `mobile-04` show the two index switches **on** for reference; every other screenshot is the default state.

## Target environment

From the attached `portfolio` folder (the GitHub Pages repo):

- `_generate_site.py` — Python script that writes `index.html` and `projects/<slug>/index.html` from a `PROJECTS: list[dict]`, a `CAREER` list and a `DATES` dict. Keep this approach: **plain HTML + one embedded `<style>` block with CSS custom properties**, zero build tooling, zero JavaScript except the ~10-line theme script described below.
- Current output uses a `<center>` + `<table border="1">` layout and a separate card-style CSS constant (`CSS`) — both are replaced entirely by this design.
- `files/*.pdf` — the three writing PDFs already exist; link them relatively (`files/<name>.pdf`).
- `projects/infurn/` and `projects/openinsider/` are hand-written pages (`external_page: True`, template in `projects/_template.html`). Regenerate them from data with the new template; the infurn before/after slider is not part of this design (see Open decisions).
- The "Progress: x/y done" line, `todo` flags, `list_meta` / `list_meta_html` chips, and `render_visual` SVG boxes are dropped.

## Fidelity

**High-fidelity.** Colours, type sizes, spacing, grid columns, tap targets and copy are final. Recreate pixel-for-pixel. Fonts are system fonts — ship no webfonts.

## Design tokens

Theme is a class on `<body>` (`body.dark`). Set `color-scheme` to match.

| token | light | dark | use |
|---|---|---|---|
| `--bg` | `#ffffff` | `#111111` | page |
| `--fg` | `#000000` | `#f2f2f2` | ink: names, titles, values, active links, active theme word |
| `--mute` | `#555555` | `#9a9a9a` | secondary text, metadata, inactive links |
| `--line` | `#e5e5e5` | `#2a2a2a` | hairline rules, figure borders, swatch borders |
| `--hover` | `#fafafa` | `#1a1a1a` | row hover background |

Type:

- `--sans`: `'Helvetica Neue', Helvetica, Arial, sans-serif`
- `--mono`: `ui-monospace, 'SF Mono', Menlo, Monaco, monospace`
- Scale (px): `20` title · `15` project prose · `14` body (page default, line-height 1.5) · `13` descriptions · `12.5` metric values (mono) · `12` contact / stack / prev-next (mono) · `11.5` pre desktop (mono) · `11` dates, repos, nav, header meta, parameter rows (mono) · `10.5` pre mobile (mono) · `10` section lines, tier lines, captions, footer (mono)
- Weights: 400 everywhere except 500 for the page title, project names, row titles, roles. Title letter-spacing `-0.01em`, line-height `1.2`.
- No uppercase anywhere; tier lines are `text-transform: lowercase`.

Rules: `1px solid var(--fg)` = "ink rule" (under the header block; above prev/next on project pages). `1px solid var(--line)` = "hairline" (every row top, nav bottom, footer top, figure borders, swatches, specimen blocks).

Spacing (px): `44` between sections (section-line `margin-top`) · `28` about top (desktop) / `24` (mobile) · `26` before a tier line · `22` meta line → title (mobile) · `20` header → nav, figure gap · `14` column gap in row grids (`16` in desktop metrics, `12` mobile metrics) · `12` nav padding, footer padding-top, about paragraph gap · `10` row vertical padding desktop (`8` for parameter rows) · `12` row vertical padding mobile · `6` section-line bottom margin · `4` title → subtitle · `3` mobile stacked-line gap.

No border-radius. No box-shadow. No transitions or animations. No icons.

## Interactions & behaviour

- **Navigation**: static links. Home → `projects/{slug}/`; project → `../../` (`← projects`, breadcrumb). Nav bar anchors jump in-page (browser default, no smooth scroll). External links (`github.com`, PDFs) open in a new tab with `rel="noopener"`. Every page load starts at the top (the prototype scrolls to 0 on navigation).
- **Mobile tap targets**: every link/button reaches ≥ 44 px via padding + negative margin without altering the visual layout (values above). Project rows are whole-row tappable; the repo link inside stops propagation. Writing rows are whole-row links.
- **Theme**: `body.dark` toggles the dark tokens. On load: `localStorage['ave-theme']` (`'light'` | `'dark'`) wins; otherwise `prefers-color-scheme: dark`. Clicking `light` / `dark` sets the class and writes the key. Put the class-setting script inline in `<head>` before the body renders so there is no flash. Also set `color-scheme: light|dark` so form controls and scrollbars follow. The toggle is a `<button type="button">`, not a link.
- **Hover** (instant, no transition): rows → `background: var(--hover)` (project, writing, results rows — not experience or parameter rows); muted links (nav, theme toggle, repos, breadcrumb, `← projects`) → `color: var(--fg)`; ink links (names, titles, contact values, prev/next, source URL) → `text-decoration: underline`.
- **Focus**: not defined in the design. Recommended: `:focus-visible { outline: 1px solid var(--fg); outline-offset: 2px }`.
- No loading, empty or error states; no forms; no animation.
- **Responsive**: desktop header, nav, footers wrap (`flex-wrap`); row grids shrink via `minmax(0,1fr)` but keep fixed columns; the desktop layout is validated from ~700 px up. Below the breakpoint switch to the mobile rules (Screens 3–4). The mock is 402 px wide (iPhone); nothing narrower was designed.

## Listing algorithm (home)

Per tier, list the `projectsPerTier` "most worked out" projects:

1. score = 10 × number of detail sections present (`about`, `params`, `metrics`, `figures`, `pre`, `stack`) + 1 if the project has a public repo;
2. sort by score desc, then `date` desc; take the first `projectsPerTier`;
3. always include `branding` (`00 arno1235`) in its tier (vibed);
4. render the picked items in drawing-number order (newest first).

With the default (1 per tier) the home page shows: engineered → **Sparkplug B**; vibed → **arno1235**, **OpenInsider**; archived → **McDo bots**. Prev/next on project pages follows this same order: Sparkplug B → arno1235 → OpenInsider → McDo bots. With 15 per tier every project is listed (13 · 9 · 5) and tier lines read `engineered · 13`, `vibed · 9`, `archived · 5`.

Only listed projects are reachable from the home page; unlisted projects may still have pages (they render `blurb` as tag and about, then stack, prev/next, footer).

## State & data model

No runtime state beyond the theme flag. Everything else is generated.

Per project (design files, `all` array — `[no, name, slug, dir, date, repo, blurb, tier]`):

| field | meaning |
|---|---|
| `no` | two-digit drawing number, `00` for the site itself, then newest → oldest `01`…`26`; shown as `arno1235-{no}` |
| `name` | display name |
| `slug` | URL segment |
| `dir` | category, lowercase-hyphen: `design` `vision-ml` `markets` `homelab-iot` `ai-wrapper` `hardware` `apps` |
| `date` | ISO `YYYY-MM-DD`; listed as `YYYY-MM` (only with `projectIndices`) |
| `repo` | GitHub repo name under `Arno1235`, empty = private. `branding` uses the Pages repo `arno1235.github.io` |
| `blurb` | one sentence, list only |
| `tier` | `e` engineered · `v` vibed · `a` archived |

Optional detail (design files, `details` object, keyed by slug): `tag`, `about[]`, `paramsLabel`, `paramsRight`, `params[[key, value]]`, `metrics[[key, a, b]]`, `figLabel`, `figRight`, `figures[[src, alt, caption]]`, `preLabel`, `pre`, `stack[]`. Projects without `details` render `blurb` as tag and single about paragraph, then stack (if any), prev/next, footer.

Derived: `visibility` = `public` if `repo` else `private`; repo URL = `https://github.com/Arno1235/{repo}`; repo label = repo name; drawing number = `arno1235-{no}`; page URL = `arno1235.github.io/projects/{slug}`.
